# 시간표 인식 실험실

에브리타임 시간표 스크린샷을 읽는 **백엔드 없는 독립 웹 프로토타입**입니다.
기존 webWallpaperTimetable 사이트에는 연결하지 않았습니다.

## 실행

```sh
npm ci
npm run setup:models
npm run dev
```

브라우저에서 http://127.0.0.1:5180/ 을 엽니다. 다른 PC에서는 모델 다운로드에 인터넷이 필요합니다.
설치 스크립트는 공식 tessdata_best 저장소에서 한국어·영어 사전학습 모델을 받습니다.
모델 합계는 27,928,729 bytes(약 27.9 MB)이며 OCR 엔진은 별도입니다.
전체 정적 배포 파일은 `npm run build`로 `dist/`에 생성됩니다.
**Python OCR 서버나 API 키는 필요하지 않습니다.** 모델 및 OCR 엔진 파일은 같은 사이트에서 제공합니다.
사용자가 선택한 사진은 브라우저 Worker에서 처리하며 인식 서버로 전송하는 코드는 없습니다.

## 기능

- PNG/JPG/WEBP 선택 및 드래그 앤 드롭
- 수업 칸 검출, 한국어·영어 OCR, 과목명과 강의실 코드 분리
- 월~금 좌표와 시간 눈금을 이용한 시작·종료 시각 추정(5분 단위)
- 시간 축 자동 인식 실패 시 첫 시간 직접 선택
- 원본의 수업 칸 표시, OCR 원문 및 수정 가능한 결과표
- 수업 삭제, 수정 결과 JSON 다운로드, 인식 취소
- 별도 Worker에서 이미지 처리, Tesseract Worker 재사용 및 모델 캐시

현재 브라우저 UI는 Tesseract.js 6.0.1과 기존 사전학습 LSTM 가중치를 사용합니다. 별도로 만든 GPU 추가 학습 모델과 구분됩니다.
부동소수점 모델을 시험할 때 7.0.0에서 코어 오류가 발생해 6.0.1로 고정했습니다.
격자, 색상 영역, 행 분할, 텍스트 필드, 시간 변환은 직접 작성한 코드입니다.

## GPU 추가 학습 결과

강의실 코드 모델을 RTX 2070에서 추가 학습했습니다. 같은 모델이 학습에 쓰지 않은 평가 사진 2장·24개 코드에서 **17/24 (70.8%) → 23/24 (95.8%)**로 개선됐습니다. 과목명·시간 OCR은 변경하지 않았으며 기존 브라우저 UI에는 새 모델을 아직 연결하지 않았습니다. 모델·분할·과적합 방지·한계는 [training/README.md](training/README.md)를 참고하세요.

## 기존 Tesseract 기준 정확도

첨부 스크린샷 9장 중 SHA-256이 동일한 1장을 제외한 **8장, 수업 92개**를 평가했습니다.
사람이 화면을 보고 작성한 정답과 비교했습니다. 이 사진들을 보고 구현을 조정했으므로
**개발 샘플 평가이며, 미지의 사진에 대한 정확도로 해석하면 안 됩니다.**

| 항목 | 결과 | 기준 |
|---|---:|---|
| 과목명 | 82/92 (89.1%) | 공백·대소문자 무시 일치 |
| 강의실 코드(빈 값 포함) | 50/91 (54.9%) | 코드 일치 |
| 시작 시각 | 91/91 (100.0%) | ±5분 이내 |
| 종료 시각 | 88/88 (100.0%) | ±5분 이내 |
| 강의실 코드가 실제 있는 수업만 | 42/83 (50.6%) | 코드 일치 |
| 모든 필드 일치 | 45/88 (51.1%) | 과목명·코드·요일·시간 |

- 가려졌거나 정확한 값을 정하기 어려운 강의실 1개, 시작 1개, 종료 4개는 해당 필드에서 제외했습니다.
- 건물 전체 설명 문자열은 채점하지 않았습니다. 강의실 **코드만** 채점했습니다.
- 시간 정답도 표를 눈으로 읽어 작성했으며, 분 단위 확정 정답이 아닌 ±5분 허용 평가입니다.
- 요일과 시작 시각을 이용해 정답 수업과 예측을 일대일 대응시켰습니다. 따라서 별도 요일 정확도는 독립 평가가 아닙니다.
- 현재 샘플의 92개 칸을 모두 대응시켰지만, 다른 시간표·주말 열·극단적 잘림에 대한 검증은 없습니다.
- **강의실 영문/숫자 혼동이 많아 자동 확정용으로는 부족합니다.** 직접 검토·수정하는 실험용입니다.

PC Node/WASM 평가 시간: 사진당 평균 5.16초, 범위 3.33–6.52초. 모델 로딩·이미지 디코딩은 제외하고 격자 탐지와 OCR을 포함합니다. 모바일 속도와 최대 메모리는 측정하지 않았습니다. 브라우저 실측은 `evaluation/browser-check.json`을 참고하세요.

## 검증 및 재평가

```sh
npm test
npm run build
node scripts/run-samples.mjs 1 2 3 4 5 6 7 8
npm run evaluate
```

마지막 두 명령은 로컬의 `samples/private/1.png` 등과 `truth.json`이 있어야 실행됩니다.
사용자 사진, 정답 전사 및 전체 OCR 원문은 공개 저장소에 올리지 않았습니다.
공개 집계는 `evaluation/summary.json`, 전체 로컬 비교는 `samples/private/evaluation.json`에 있습니다.
개발 서버는 로컬 평가 사진이 있을 때만 개발용 선택 버튼을 표시합니다. 프로덕션 빌드에는 이 기능이 없습니다.

다른 사진의 정답 형식:

```json
{"method":"manual transcription","samples":[{"id":"1","sha256":"IMAGE_SHA256","classes":[{"day":"월","name":"예제수업","roomCode":"A101","startMinutes":540,"endMinutes":600}]}]}
```

읽을 수 없는 값은 `null`, 명시적으로 강의실이 없는 칸은 `""`로 구분합니다.
정답과 예측이 같은 사진인지 SHA-256으로 확인하고 중복 입력은 거부합니다.

## 알려진 한계

- 과목명·교수명 분리, 영문 과목의 줄바꿈, P/0·B/8·K 등의 OCR 혼동
- 화면 밖으로 나간 텍스트 복원 불가; 하단 가림 판정 역시 휴리스틱
- 시간 축 자동 보정은 시작 6~14시를 우선하며 이후 시작 표는 직접 지정 필요
- 월~금 5열 스크린샷을 대상으로 구현; 주말·임의 표 양식 미지원
- OffscreenCanvas, Web Worker, WebAssembly를 지원하는 브라우저 필요
- 공개 모델 파일 자체가 작아도 실행 메모리는 더 필요함; 모바일 메모리 검증 전
